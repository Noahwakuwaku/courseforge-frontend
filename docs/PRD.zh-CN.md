# CourseForge 产品需求文档

版本 1.3 · 2026-11-16

## 目标与范围

面向「橘智」平台创作者，批量、快速生成可用的系统性课程，在人工时间、模型成本与质量之间取得平衡。

本期覆盖课程规划、分阶段生成、人工验收和接口同步。可用标准：目标与前置知识明确，学习顺序合理，正文覆盖纲要，关键事实经人工核对，已生成练习与正文一致。系统记录人工结论，不自动证明内容正确。

## 执行流程

默认路径：创建计划 → 确认结构 → 验证样本 → 批量生成 → 逐门验收 → 同步草稿。

| 阶段 | 执行逻辑 | 进入下一步的条件 |
| --- | --- | --- |
| 创建计划 | 用户输入主题，系统生成课程目录与层级；一次最多 5 个主题 | 目录生成并保存成功 |
| 确认结构 | 用户检查课程范围、学习顺序与知识覆盖 | 用户确认当前结构 |
| 验证样本 | 选择一门代表课程，分别生成纲要和材料，再阅读检查 | 样本当前版本验收通过 |
| 批量生成 | 先补齐所选课程的纲要，再由用户发起材料生成；练习按需生成 | 需要交付的课程已具备纲要和材料 |
| 逐门验收 | 检查目标、事实、深度与衔接；通过则标记验收，否则填写修改意见 | 所选课程当前版本验收通过 |
| 同步草稿 | 展示接口字段；填写地址并检测，选择课程、预览数据、确认发送 | 接收端逐项返回对应版本的成功结果与草稿 ID |

样本先行是默认引导，不是强制门槛；熟悉流程的用户可直接选择课程批量操作。允许交付已验收的部分课程，不必等待整套计划全部完成。

## 执行规则

- 生成依赖：纲要 → 材料 → 可选练习。各阶段独立发起，不自动连带执行；生成前确认类型、范围和可能产生的模型费用。
- 批量范围：正常生成跳过已有内容；重生成单独确认，可能覆盖旧内容，当前不支持版本回滚。
- 审核有效性：纲要、材料或练习变化后，旧审核失效，需重新检查；课程结构变化后需重新确认计划。
- 同步条件：计划已确认，所选课程纲要与材料齐备、当前版本已验收，接口检测通过。当前计划没有正在生成或结果待确认的任务，上一次同步已确认结束后，才能发送新批次。只同步草稿，不自动发布、不再次调用模型。

## 异常处理

- 创建失败：保留主题输入，允许修改后重试。
- 生成失败：保留成功项与失败明细，只重试明确失败项。超时不等于失败；有任务 ID 则重新查询，无 ID 则先核对后端，不盲目重发。刷新后不恢复生成任务跟踪，后台任务可能继续执行。
- 同步异常：明确失败项可单独重试；版本冲突先处理再提交。结果未知时保留原编号与内容，刷新后仍用原请求重试，依赖接收端去重；未确认前不发新批次。

## 验收与边界

- 界面能明确显示下一步、操作范围与逐项状态；生成完成、人工验收和同步成功分别记录。
- 审核记录仅存当前浏览器。尚无真实费用统计、预算封顶和跨设备审核；短期同步令牌仅存页面内存。
- 橘智同步客户端已实现，接收端仍需提供鉴权、去重、冲突处理与草稿保存。字段及返回要求见项目内的 [同步接口协议](JUZHI_SYNC_API.zh-CN.md)。
- 示例模式不调用模型、不发送真实同步请求。交付检查覆盖正常流程、部分失败、断线重试、内容变更复核及窄屏操作。

效果评估：记录已验收课程数、主动人工时间、全批模型费用和首轮验收通过率，与原流程比较。
